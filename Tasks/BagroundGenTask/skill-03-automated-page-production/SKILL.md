# Skill 03 Automated Page Production

Produce only the requested chapter and page range. Stop after delivering the batch and wait for author review; only a later explicit user instruction can override that stop. A request to continue never promotes earlier artwork to approved. Resolve routine design decisions independently. Follow later explicit user corrections within their stated scope. Internal review never constitutes author approval.

Read these references as each stage begins:

- [Sources and continuity](references/sources-and-continuity.md): input verification, manual-review reuse, exact content and approval states.
- [Maths-page art direction](references/maths-page-art-direction.md): required consideration of scenery extension, character placement, corners and fair-related devices before artwork and during final visual review.
- [InDesign workflow](references/indesign-workflow.md): native assembly, reusable helpers, fonts, actual Adobe export and retry handling.
- [Review and checkpoints](references/review-and-checkpoints.md): image/page gates, 40-check evidence, resumable records and packaging.

Use the current approved manuscript, manual, checklist, support package and visual masters as project inputs. Do not substitute this skill's summary for reading them. Keep project-specific manuscripts, artwork, author decisions and review records in the project package, not in this skill. Do not assume files or a runner are present merely because a previous chat used them.

## 1. Verify the batch before artwork

1. Locate the exact approved sources and prior delivery. Record filenames, versions and SHA-256 hashes. Read manuscript global production notes, complete assignments and every panel/page note for the range, plus relevant neighbouring context. Read the current complete production checklist, including examples and carried-forward lessons, for every batch.
2. Read the support package's workflow, manifest, hashes, applicable briefs, asset register, diagrams and review requirements. Compare derived inputs to the actual source. Refresh stale inputs; never let an old manifest override the manuscript.
3. Verify the manual against a reusable full-review record. Reuse a full review only when the exact hash matches and the record verifiably documents all manual pages, sections and visual examples. Otherwise review the complete manual including every example. For each current page, reread applicable sections and inspect their examples even when full review is reusable. Carry the full-review evidence forward.
4. Inspect relevant approved character sheets and locations, the latest approved preceding page and recent relevant character appearances. Label delivered-but-unapproved proofs separately. Preserve the known lighting, repair state, props and ownership through the page turn.
5. Discover the currently callable InDesign runner/export route. Verify the working configuration, using a small actual export when availability is unproven or the configuration changed. Do this before substantial artwork. Do not assume the support ZIP includes a runner. Stop artwork on a genuine missing-route blocker; report precisely. Never silently replace InDesign with another page compositor.

Reuse verified source extraction and unchanged manual-review evidence. Do not reread every unchanged document or rebuild every tool unnecessarily. Source verification and full checklist reading remain mandatory for each batch.

## 2. Plan all requested pages, then produce one at a time

Prepare rough text-first layouts for the whole batch before generating artwork. They need not be polished pages. Record for every page:

- Teaching/story purpose, reading route, panel/source order and complete content inventory.
- Exact text, emphasis, numbering, maths notation, worked steps, answers, diagrams, asides and intentional unanswered activities; distinguish production-only instructions.
- Required visual mathematical evidence, including counts, dimensions, orientation and intermediate states.
- Composition, applicable manual sections/examples and recognisable ChandRush treatment.
- Character identity, authored action, varied meaningful pose, location, lighting, repair state and prop owner.
- Approved assets to reuse; missing views or local edits; actual pixel dimensions, crop and effective PPI at planned size.
- Space for editable lettering, balloons, exact diagrams and inscriptions, with suitable margins and perspective on their actual objects.
- Unused regions beside and above a character, how the setting will extend into suitable regions, or a specific readability/continuity reason for keeping them open. Record the book name, chapter identity and page number as subordinate page furniture.

Design around complete teaching units. Keep questions, explanation, working and answers visibly connected. Preserve page boundaries and panel ownership. Never shorten, solve an intentionally unanswered activity, add an interesting quote or move content to another page to make the design fit. Raise genuine source conflicts instead of guessing.

Prefer compositions suited to the content over repeated templates. Use plaques, fair signage, machinery, supported objects and varied corners when appropriate. If using a book, make its form clearly visible. Extend scenery into unused space while protecting teaching and purposeful breathing room. Avoid tiny decorative characters or ornament that competes with the maths. Do not apply old page-specific requests, such as a moon path on Page 79, to unrelated pages automatically.

On a spacious maths-focused page with a required or permitted character aside, actively extend a coherent fragment of that character's setting into suitable unused space. Inspect the left, right and upper regions; do not leave the figure confined to a small scenic island by default. Plan and review this at full-page scale. Extend the scenery itself when needed instead of simply enlarging the same crop or filling gaps with unrelated ornaments. Read the maths-page art-direction reference for the complete decision and review rules.

## 3. Review each image immediately

Work through one page's required images in source order. Reuse suitable approved artwork first. Generate or edit only what is missing, using the available image-generation/editing capability and its applicable skill instructions.

For each image:

1. Set the intended placement, crop, lettering surfaces and reference masters before the call. Carry forward the previous verified scene state and approved identity references.
2. Create one image or local edit. Inspect that result before requesting the next image. Check identity, authored action, limbs/hands, meaningful gesture, prop ownership, support/contact shadows, lighting, repair state, unintended lettering and visual mathematical evidence.
3. Inspect the intended crop at page scale and close detail. Where text, diagrams or inscriptions interact with the image, test their exact editable overlay in a local composition immediately. An attractive isolated image is not sufficient.
4. Check actual native pixels and effective PPI; target at least 300 PPI. Do not treat export resolution or simple upscaling as recovered detail. Keep important story imagery prominent.
5. Correct locally and reinspect the changed region and neighbours. If a defect recurs, reconsider geometry, pose, reserved space or reference clarity before generating another full image. Avoid uncontrolled variants.
6. Save the chosen asset revision, hash, placement and concrete observations. Mark it internally reviewed, not author-approved. Proceed to the next image only after fixable defects are resolved.

Design figures and scenery together. Keep figures grounded and contact shadows crisp. Blend outer vignette edges into the exact surrounding page colour where suitable; do not blur or fade the character, meaningful props, feet or contact shadows. Avoid rectangular remnants and white halos. Use playful, funny or cool poses suitable for an 11-year-old urban child when the authored action permits. Preserve continuity, comprehension and the story's actual state. Do not stretch or mirror artwork to make it fit.

## 4. Assemble, export and review this page before the next

Assemble native InDesign objects from the verified plan. Use the supplied reusable native IDML primitives or another verified InDesign runner; use custom page layouts. Keep exact text, mathematical diagrams and lettering editable and separable from raster illustrations. Do not flatten the whole page.

- Use 12 × 9 inches, landscape, RGB and zero bleed.
- Apply the approved manual's font roles. Keep reading text and essential labels normally at least 14 pt; use 13 pt only with explicit page-specific permission. Preserve source emphasis and mathematical typography.
- Make inscriptions sit within the correct card, plaque or machine face, following its perspective and margins. Support realistic decorative objects. Keep compact balloon tails clear of faces, hair, hands and labels.
- Check text fit, complete source placement, exact diagrams and calculations before export. Inspect image-plus-lettering integration now.

Default to a self-contained one-page source for each page. Upload that current page revision once and reuse the upload for its export/retries. This supports the sequential workflow without uploading a growing batch repeatedly. A package of matching one-page editable documents is acceptable unless the user explicitly requires a single multi-page editable document. If using one shared batch document, track per-page dependencies and reuse unaffected exports only after verifying their consistency with the final source.

Export the page through actual Adobe InDesign: RGB, zero bleed, maximum quality, 300 PPI raster settings. Do not request a combined batch export first. Avoid duplicate requests while a job is running. Retain each successful export and its receipt. If the download is damaged or incomplete, retry the existing download before creating another export. Validate file size where reported, one page, correct dimensions, opening and rendering.

Then perform the page review against the actual exported PDF:

1. Reopen the complete current checklist after export within the batch. Revisit this page's manuscript assignments, applicable manual sections and visual examples.
2. Inspect at normal tablet/laptop size and close detail. Verify every calculation, visual mathematical fact, reading route, character identity, physical integration and incoming continuity.
3. Complete all 40 checks for this page with PASS, NEEDS FIX, NOT CHECKED or NOT APPLICABLE. Give every PASS a specific observation tied to the current exported revision. Explain every NOT APPLICABLE. Technical counts and the presence of blocks never establish design quality.
   Explicitly review whether spacious maths-page scenery uses the available composition well. Record the actual extended regions and teaching clearance under the applicable existing checks, including B03, C02, C07 and F03/F08; do not add a fabricated 41st checklist item. A small character image beside unexplained unused space is not an automatic design PASS.
4. Correct fixable defects, re-export affected pages, reinspect and update affected review entries. Check transparency, colours, crops and neighbouring elements after changes.
5. Save a resumable page checkpoint before proceeding. Complete this page's review before generating the next page's art. Do not ask the user to approve each internal checkpoint.

Do not claim live font or overset preflight unless actually performed in a capable InDesign environment. Record unavailable required checks precisely as NOT CHECKED. Distinguish a qualified review proof from a fully checked page. A known unavailable external preflight need not prevent completing other authorised work, but must remain visible in delivery. Never mark it PASS from IDML metadata, outline appearance or simulated text-fit calculations.

Run independent objective checks in parallel only where they do not bypass these creative review gates. Do not generate all pages' artwork first. Do not wait until the final combined PDF to inspect an InDesign export.

## 5. Final batch review and delivery

Combine only validated InDesign-exported pages in manuscript order, preserving PDF page objects without rasterising, recomposing, downsampling or changing colours. Combining is packaging, not page assembly. Validate the combined file against the individual exports and inspect page count, order, overall appearance and continuity across every page turn.

Re-export only pages affected by changes, including shared assets, styles, fonts, diagrams or assembly code. Reuse an unaffected export only with evidence that its source and dependencies remain consistent. Never mix obsolete exports into the final package.

For a limited correction, list the authorised pages, panels and changes before editing. Compare the old and revised renders outside that scope, using a pixel comparison where useful; investigate any unintended change. After scenery extensions or fades, specifically compare paper, table fills, ink, surrounds and neighbouring images for colour shifts or opacity changes. Reopen an earlier PASS when author feedback reveals a missed defect.

Deliver:

- One combined batch PDF.
- Matching editable InDesign sources; state IDML, INDD or both accurately. Include linked assets, required fonts where redistribution is permitted, licenses, assembly scripts and relevant project configuration. Distinguish an export-outline variant from the live-text editable source if used.
- One page-specific review record covering all 40 checks per page, corrections and unresolved limitations.
- Exact source hashes, full reusable manual-review record/evidence, asset and export records, and final checkpoints for the next chat.

Save user-facing deliverables using the current file-persistence workflow. Keep delivery brief, state incomplete checks precisely, and leave author approval pending. Do not start another batch.
