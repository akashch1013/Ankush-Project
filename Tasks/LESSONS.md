# LESSONS: rules learned from the user's feedback

Every agent reads its own section before working. The master adds a dated rule here after each piece of feedback (raw words go to FEEDBACK.md). Newer rules override older ones and any default in a skill or guide.

## All stages
- 2026-11-25 · **Workflow (user: faster, parallel, fewer tokens, same quality).** A plain request ("make pages 6 to 10") runs the full production run in `comic-master`: plan → briefs (layout first) → prompts → **ONE image batch per wave for all pages** → page shells built *while* the batch runs → letter on the real art → math-checker per page in parallel → **one deliverable: combined PDF + ONE artifact with every requested page** (`pagekit.py set`). Spawn independent workers in one message; continue a worker with SendMessage instead of re-spawning. Sonnet for low-reasoning jobs (math-checker, production-assistant, mechanical fixes), Opus for design/prompts/visual QC.
- 2026-11-25 · **Stop at 3 generations, strictly.** imggen.py now refuses a 4th call on any image (no --force). Spend the effort on the first prompt instead: PANEL-GUIDE §7 checklist + `promptlint.py` (batch build refuses lint FAILs).
- 2026-10-27 · Image quality is `high` by default and `xhigh` only for genuinely hard images. `max` is never used without asking ("max is too much").
- 2026-11-04 · All image generation goes through the Batch API, including fixes and the critical path.
- 2026-11-22 · Samples also go through a small batch. No immediate calls until the user explicitly says so.
- 2026-11-04 · After 3 calls an image is accepted as-is: log the defect, never make a 4th call.
- 2026-11-22 · Keep cost low without losing quality: reuse art (zoom crops, library), attach only the references that are needed, use 1K-class sizes.

## Backgrounds (stage 1)
- 2026-10-21 · Reference images carry painted titles, white labels and arrows: tell the model to ignore them, or they leak.

## Panel art (stage 2)
- 2026-11-25 · **Character references come from `Tasks/CHANDRUSH CHARACTERS/`** (new sheets: Ira, Kabir, Pip, Veer, Veer clown disguise, wooden clown, wooden fair/kitchen helpers, supporting cast, updated Tara, plus three height charts). Filenames don't name the character: use `pipeline/cast.json` / `cast.py refs`. Attach the sheet of EVERY visible character (no "describe instead") and the height chart when 2+ characters share a panel.
- 2026-11-25 · **Never alter the background to fit the story.** Objects in the plate (cart, handle, gate, controller, stalls) keep their exact shape, position and orientation in every panel. Stage the action *inside* the given background: study the plate, decide where each character must stand so the beat happens naturally (e.g. Tez walks on the line of the cart's existing handle and bumps its real tip), then write the prompt. Before briefing any panel, read the previous and next pages' panels and art, so positions, props and states carry over with no continuity jump. (P002: a new handle across the street was rejected.)
- 2026-11-25 · **Characters come only from their sheets.** Draw each visible character exactly as on its character sheet (face, age, build, hair, costume); never re-imagine them from the manuscript's description. Every visible named character gets their sheet attached, even small or background figures. **Tara's expression is always that of a calm, wise old lady** (the sheet's Warm / Thoughtful / Reassuring / Watchful / Resolute): no open-mouthed, animated or cartoon expressions. (P003)
- 2026-11-22 · Bubbles and captions are HTML overlays. Never paint them; reserve calm empty areas for them.

## Art direction (stage 2.5 + 3), newest: governs the look
- 2026-11-25 · **The current design is very good: keep it, and put creativity + randomness on every page while holding the overall structure.** `PdfSheetsGenTask/design/PAGE-DESIGN.md` is now the single consolidated card of every decision (fixed system vs varied axes, scorecard). `pipeline/vary.py --write` gives each page a seeded variation card (grid, panel accent, border build, entry corner, field, hero slot, gutter, light link) that never repeats a neighbour; start from it, deviate only for a content reason.
- 2026-11-25 · **P005 (B1-light lesson page: cream field, cut-out Ahana in a corner, two frosted plate strips, gauge down the middle, boxes on the right) was rejected: "design is not that good … build the pages like an actual book designer".** Design like a professional illustrated-textbook designer: (1) a real typographic grid: fixed margins, a column grid and a baseline, and every block snapped to it, no floating boxes; (2) one clear entry point and a deliberate reading path (big display moment → body → answer), with strong scale contrast; (3) whitespace is shaped, never leftover: no empty holes, no half-filled columns; (4) images are framed with intent (full-bleed band, framed plate, or a properly composed spot illustration), never cropped cut-outs stranded in a corner or ragged image slivers; (5) the lesson's maths picture is the hero, big and beautiful; (6) a consistent running head + folio system across the book; (7) think in spreads: facing pages balance, and the book has a rhythm of dark story pages and light lesson pages.
- 2026-11-24 · **P107 (story, Food Street border) is loved, but every page must feel new.** Keep consistent only the book's system: V09 type sizes/fonts, text-role objects (caption paper, speech balloons), the moonclock folio/page number and border construction rules. Vary per page: field colour, border material/motif (taken from that page's own location), panel grid and shapes, hero framing. Never repeat the previous page's colour story or layout. Think like a book designer: pacing across spreads, a reason for each page's shape.
- 2026-11-24 · **Never put text over a busy image.** A plate/scene behind reading text is used only if the text stays fully readable; otherwise use a calm field and put the picture in a panel.
- 2026-11-23 · **B1 "Ledger Plate" (CH01 P039) is approved** ("The latest sample was good").
